# MetaGuard v0.3 Policy Routing Design

Dokumen ini merancang routing deterministik di atas policy registry dan
metadata-filtered retrieval. Router bukan legal decision maker, tidak memakai
LLM, dan tidak menentukan bahwa suatu organisasi wajib tunduk pada policy
tertentu. Pilihan context tetap dikendalikan pengguna dan dapat direview.

## 1. Separation of Concerns

Empat konsep harus dipisahkan:

| Konsep | Makna |
| --- | --- |
| Governance context | Apakah dataset dianalisis sebagai data pemerintah/publik atau generic non-government |
| Domain | Konteks sektor data, misalnya healthcare, education, environment, generic |
| Policy pack | Kelompok dokumen yang dapat dipilih router |
| Topic | Filter sempit untuk evidence/rule tertentu |

Policy pack bukan domain. Satu domain dapat menggunakan pack sektoral dan pack
governance generic. Satu policy teknis dapat topic-routed tanpa menjadi default
pack seluruh domain.

## 2. Governance Context

Nilai MVP:

```text
government_public
generic_non_government
```

Dua nilai cukup untuk v0.3 karena tujuan utamanya menghindari aktivasi policy
pemerintah secara otomatis pada dataset umum. Jika status dataset tidak jelas,
UI harus meminta pilihan eksplisit; jangan menebak dari nama kolom atau Gemini.

Behavior aman:

- `government_public`: `government_generic` eligible untuk governance needs;
- `generic_non_government`: `government_generic` tidak eligible secara
  default;
- domain sektoral pada `generic_non_government` memberi konteks rule/domain,
  tetapi regulasi pemerintah sektor tersebut tidak otomatis dianggap wajib;
- explicit opt-in policy research dapat menjadi fitur terpisah di masa depan,
  bukan fallback diam-diam.

## 3. Policy Pack Model

Initial packs:

| Pack | Domain relation | Default eligibility |
| --- | --- | --- |
| `government_generic` | Cross-domain governance | `government_public` + governance need |
| `healthcare` | Healthcare data governance | `government_public` + `healthcare` |
| `education` | Education data governance | `government_public` + `education` |
| `environment` | Environment data governance | `government_public` + `environment` |

Phase-2 dapat menambah pack/subprofile seperti `healthcare:puskesmas` atau
`environment:air_quality`, tetapi router harus membaca deklarasi registry,
bukan memiliki `if` khusus untuk setiap dokumen. Policy topic yang belum ada di
initial corpus tidak boleh menghasilkan filter yang seolah-olah tersedia.

## 4. Router Contract

### 4.1 Input

```text
governance_context: stable ID
selected_domain: stable ID
evidence_need: stable ID
optional_topic: stable ID | null
active_findings: compact finding summaries/provenance only
registry_snapshot: validated registry view
```

`active_findings` tidak memuat DataFrame atau seluruh evidence. Router hanya
memerlukan check/rule ID, category, domain, concept IDs, dan provenance type
yang relevan.

### 4.2 Output

```json
{
  "governance_context": "government_public",
  "selected_domain": "education",
  "evidence_need": "metadata_governance",
  "eligible_policy_packs": ["government_generic", "education"],
  "eligible_document_types": ["governance_policy", "sectoral_data_governance"],
  "optional_topics": ["metadata"],
  "eligible_policy_ids": [],
  "routing_reasons": ["..."],
  "warnings": []
}
```

`eligible_policy_ids` boleh kosong ketika pack/type filter sudah cukup; bila
diisi, nilainya harus berasal dari registry. Output JSON-safe, urutan stabil,
dan tidak berisi callable atau Chroma object.

### 4.3 Deterministic rules

1. Validasi context/domain/evidence need terhadap allowlist.
2. Ambil policy current dan verification-complete saja.
3. Terapkan governance eligibility.
4. Terapkan domain eligibility.
5. Terapkan evidence need ke allowed document types/topics.
6. Terapkan optional topic hanya jika tersedia dalam registry.
7. Urutkan pack/policy berdasarkan registry priority yang eksplisit.
8. Jika hasil kosong, return blocked/not-applicable dengan alasan; jangan
   fallback ke seluruh corpus.

Tidak ada arbitrary expression execution. User tidak dapat mengirim raw Chroma
`where` object. Filter dibangun dari output router yang sudah divalidasi.

## 5. Routing Examples

### Government education metadata

```text
government_public + education + metadata_governance
-> government_generic + education
-> governance/metadata document types
```

### Government environment technical topic

```text
government_public + environment + technical_standard_support
+ optional_topic=air_quality
-> environment pack/topic only when a verified eligible policy exists
-> government_generic only if a separate governance need is also active
```

### Generic non-government dataset

```text
generic_non_government + generic + data_quality
-> no government policy pack by default
-> retrieval not applicable, with an explicit user-facing reason
```

### Non-government education dataset

```text
generic_non_government + education + domain_semantic_support
-> domain rule context may remain active
-> government education policy is not automatically routed
```

## 6. Evidence Need Model

Pertahankan tiga stable ID v0.2:

- `metadata_governance`;
- `data_quality`;
- `accountability`.

Tambahkan hanya dua ID ketika implementasi domain/provenance membutuhkannya:

- `domain_semantic_support`: evidence untuk contextual/domain finding yang
  mempunyai provenance sektoral;
- `technical_standard_support`: evidence untuk rule/konsep yang secara
  eksplisit membutuhkan technical standard.

`data_quality` dipertahankan sebagai compatibility ID walaupun query-nya masih
governance-oriented. Jangan membuat evidence need per finding. Satu run dapat
memiliki beberapa need; setiap need diroute secara independen dan hasilnya
digabung deterministik.

## 7. Query Building

Query builder v0.3 menerima routing result, bukan raw user filter:

```text
evidence_need
+ governance_context
+ selected_domain
+ compact finding/concept provenance
+ optional topic
```

Gunakan template terkurasi per evidence need. Query akhir dapat berupa:

1. generic governance query untuk need v0.2;
2. domain-qualified query untuk domain support;
3. finding-aware query yang hanya menyertakan stable concept/rule terms;
4. kombinasi singkat dari 1-3, dibatasi jumlah query.

Jangan memasukkan seluruh descriptions/evidence ke query. Jangan memakai Gemini
untuk rewriting. Bounded retry tetap maksimal dua attempt dan hanya memperbaiki
need/topic yang belum covered. Refined query harus berbeda, tidak kosong, dan
tetap menggunakan filter eligibility yang sama atau lebih sempit.

Query group v0.3 sebaiknya menyimpan `need` secara eksplisit:

```json
{
  "need": "metadata_governance",
  "query": "...",
  "routing": {
    "policy_packs": ["government_generic"],
    "document_types": ["metadata_governance"]
  },
  "results": []
}
```

Ini mengurangi ketergantungan v0.2 pada klasifikasi phrase query.

## 8. Chroma Filter Builder

Filter builder menerima IDs hasil registry/router dan menghasilkan canonical
`where`. Contoh:

```json
{
  "$and": [
    {"effective_status": {"$eq": "current"}},
    {"policy_pack": {"$in": ["government_generic", "education"]}},
    {"document_type": {"$in": ["governance_policy", "sectoral_data_governance"]}}
  ]
}
```

Rules:

- values berasal dari allowlist registry;
- list kosong tidak menghasilkan `$in: []`;
- satu condition tidak perlu dibungkus `$and`;
- ordering condition dan values stabil;
- topic filter hanya digunakan jika topic scalar tersedia;
- current/effective gate tidak boleh dihilangkan oleh query user;
- unit tests menguji bentuk filter dan hasil isolation, bukan hanya truthiness.

## 9. Retrieval Result Contract

Contract minimum v0.2 tetap:

```json
{
  "chunk_id": "...",
  "source": "...pdf",
  "page": 12,
  "text": "..."
}
```

Additive mandatory v0.3 untuk routed result:

```json
{
  "policy_id": "GOV-BPS-METADATA-5-2020",
  "policy_pack": "government_generic",
  "domain_id": "generic",
  "document_type": "metadata_governance"
}
```

Additive optional: `classification`, `effective_status`, `topic`, dan
`distance`. Distance tetap technical retrieval output dan tidak menjadi bukti
semantic truth. Semua value JSON-safe; tidak ada embedding/vector.

## 10. Domain and Policy Alignment

Evidence sufficiency dan alignment dinilai terpisah. Model yang direkomendasikan
bersifat multi-dimensional:

```json
{
  "coverage_status": "complete|partial|none",
  "unique_evidence_status": "adequate|limited|none",
  "source_diversity_status": "diverse|single_source|none",
  "policy_pack_alignment": "aligned|partial|not_aligned|not_applicable",
  "domain_alignment": "aligned|partial|not_aligned|not_applicable",
  "overall_retrieval_readiness": "ready|needs_retry|human_review",
  "reasons": [],
  "missing_needs": [],
  "misaligned_policy_ids": []
}
```

Alignment bersifat deterministik berdasarkan requested domain/pack/need/type/
topic dan metadata registry. Ia tidak mengukur legal applicability, semantic
correctness, atau apakah isi chunk benar-benar menjawab pertanyaan substantif.

Evidence dari pack tidak eligible tidak boleh menaikkan coverage aligned.
Evidence tersebut dapat dicatat sebagai misaligned, tetapi tidak diteruskan ke
Gemini pada normal path.

## 11. Sufficiency Migration

Pertahankan output dan formula v0.2 (`status`, `score`, counts, coverage,
duplicates, reasons) untuk compatibility. Tambahkan assessment alignment dan
`overall_retrieval_readiness` sebagai sibling/additive data.

Normal Gemini readiness v0.3 memerlukan:

```text
v0.2 sufficiency.status == sufficient
AND overall_retrieval_readiness == ready
AND evidence berasal dari eligible routed corpus
AND explicit human approval
```

Jangan menggabungkan seluruh dimensi menjadi satu angka baru pada MVP. Model
multi-dimensional lebih auditable dan mencegah score tinggi menyembunyikan
domain mismatch. Threshold v0.2 tetap heuristic MetaGuard, bukan compliance
score.

## 12. Bounded Retry Interaction

- Attempt 1 memakai query/filter deterministik awal.
- Retry hanya bila missing need/topic dapat diperbaiki secara deterministik.
- Retry memakai eligibility yang sama atau lebih sempit; tidak memperluas ke
  seluruh corpus.
- Evidence final cumulative dengan conservative deduplication.
- Duplicate antar-attempt tidak menambah sufficiency/alignment.
- Bila coverage lengkap tetapi alignment gagal dan tidak ada refinement aman,
  stop dan require human review.
- Attempt history mencatat routing fingerprint/filter summary, bukan full
  evidence duplikat.
- `MAX_RETRIEVAL_ATTEMPTS` tetap 2 kecuali milestone berbeda menyetujui
  perubahan.

## 13. State and Fingerprint Impact

State kecil yang diperlukan:

```text
governance_context
selected_domain
policy_registry_fingerprint
policy_corpus_fingerprint
active_policy_packs
policy_routing_result (ringkas)
evidence_alignment
```

Jangan menyimpan seluruh registry di session state. Perubahan governance
context, domain, registry/corpus fingerprint, active pack, atau routing-relevant
topic harus mereset evidence, sufficiency/alignment, retry history, Gemini,
traceability, report, serta agent state/audit downstream.

Same-fingerprint Streamlit rerun mempertahankan state dan tidak menjalankan
retrieval/Gemini secara otomatis. Domain/context harus masuk fingerprint aktif;
nilai subprofile/topic yang tidak aktif harus dinormalisasi agar tidak memicu
reset palsu.

## 14. Traceability and Report Impact

Reviewer v0.2 tetap memvalidasi `chunk_id`, `source`, dan `page`. Metadata baru
memungkinkan trace tambahan tanpa second LLM:

```text
Gemini citation
-> chunk_id
-> policy_id
-> source/page
-> policy_pack
-> domain/evidence need
```

Candidate additive report fields:

- `analysis_context` (`governance_context`, `selected_domain`);
- `policy_routing` dan `active_policy_packs`;
- `evidence_alignment`;
- metadata policy additive pada setiap evidence result.

Contract tetap realistis sebagai additive bila field v0.2 tidak dihapus dan
consumer lama boleh mengabaikan field baru. Schema bump baru diperlukan jika
shape existing evidence diubah, bukan hanya karena metadata additive.

## 15. Safe Fallback and Failure Behavior

- Unknown domain -> `generic`, tanpa domain-specific pack.
- Unknown governance context -> block routing sampai pilihan eksplisit.
- Missing registry/file -> ingestion/routing error yang terlihat, bukan global
  retrieval fallback.
- Empty eligible corpus -> evidence unavailable/not applicable; Gemini tidak
  dijalankan.
- Unsupported topic -> warning dan human review, bukan fuzzy mapping.
- Chroma filter error -> structured retrieval failure; jangan retry tanpa
  memperbaiki input/filter.
- Policy status unresolved -> ineligible sampai verification selesai.

User-facing text harus menjelaskan bahwa routing dan sufficiency adalah
heuristic readiness MetaGuard, bukan kesimpulan hukum.

## 16. Test Matrix for Future Implementation

1. Router `government_public + generic` hanya memilih government generic.
2. Router healthcare/education/environment memilih pack domain yang tepat.
3. `generic_non_government` tidak mengaktifkan government packs.
4. Unknown context/domain gagal aman.
5. Metadata filter memakai scalar dan canonical `$and/$in`.
6. Tidak ada cross-domain result leakage.
7. Result v0.2 tanpa metadata baru tetap valid pada compatibility path.
8. Routed result memiliki policy/pack/domain/type.
9. Mechanically sufficient tetapi misaligned tidak `ready`.
10. Aligned evidence dengan full need coverage dapat `ready`.
11. Retry tetap maksimum dua dan mempertahankan filter eligibility.
12. Domain/context change mereset downstream state.
13. Same fingerprint tidak mengulang retrieval.
14. Traceability tetap memvalidasi legacy fields dan membawa metadata additive.
15. Report JSON-safe dan tidak mengandung registry penuh/vector/API key.
16. Seluruh 212 regression tests v0.2 tetap lulus.

## 17. Unresolved Decisions

1. Apakah `generic_non_government + sector domain` selalu tanpa policy, atau
   memiliki explicit opt-in reference mode pada milestone sesudah MVP.
2. Apakah topic metadata dikurasi per document atau per chunk.
3. Apakah `data_quality` tetap dipetakan hanya ke governance evidence atau
   dipecah setelah rule-provenance implementation tersedia.
4. Bentuk final `document_type` vocabulary dan registry priority.
5. Bagaimana UI membedakan `not_applicable` dari `insufficient` tanpa menambah
   stage agent yang tidak perlu.
