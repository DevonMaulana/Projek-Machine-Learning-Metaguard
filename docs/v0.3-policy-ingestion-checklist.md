## 3. Official PDF Acquisition Gate

Terapkan checklist ini untuk empat file baru dan integrity re-check dua file
existing.

### Identity and official source

- [ ] URL berasal dari website/JDIH resmi penerbit atau source pemerintah resmi.
- [ ] Title, number, year, authority, dan document type cocok dengan registry.
- [ ] Status current/effective telah diverifikasi manusia.
- [ ] Amendemen, replacement, dan revocation telah diperiksa.
- [ ] Tidak ada ambiguity yang belum dicatat pada `revision_info`.
- [ ] Source URL dicatat sebagai metadata; aplikasi tidak auto-download.

### File integrity

- [ ] File benar-benar PDF, bukan HTML/error page dengan ekstensi PDF.
- [ ] PDF dapat dibuka dan dibaca manusia.
- [ ] Page count masuk akal dan dicatat pada acquisition record.
- [ ] Teks dapat diekstrak dengan `pypdf`; kebutuhan OCR dilaporkan, bukan
      diselesaikan diam-diam.
- [ ] SHA-256 dihitung setelah file final diperoleh.
- [ ] File name mengikuti konvensi repository dan `local_file` relatif cocok.
- [ ] Tidak ada attachment/macro/script yang dieksekusi.

### Registry and review

- [ ] `policy_id` unik dan stabil.
- [ ] Pack/domain/type/classification/status/topics/routing scope tervalidasi.
- [ ] `verification_state` memenuhi ingestion gate.
- [ ] RAG suitability dan deterministic-provenance suitability tidak tertukar.
- [ ] Dokumen technical/reference tidak menjadi default global tanpa routing.
- [ ] Reviewer manusia menyetujui entry sebelum file masuk corpus.

## 4. Registry Validation Checklist

- [ ] Registry JSON dapat diparse tanpa dependency baru.
- [ ] Semua required fields tersedia dan tidak kosong.
- [ ] Enum/ID hanya berasal dari vocabulary allowlisted.
- [ ] `year` integer; value Chroma filterable memakai scalar primitive.
- [ ] Semua `policy_id` dan `local_file` unik.
- [ ] Semua local path relatif dan tetap di bawah `data/policies/`.
- [ ] Setiap file ada, readable, dan checksum sesuai sebelum ingestion.
- [ ] Non-current/unverified policy ditolak dari active corpus.
- [ ] Tidak ada secret, API key, executable expression, callable path, atau raw
      user filter.
- [ ] Registry fingerprint canonical dan deterministic.

## 5. Ingestion Dry-Run Checklist

- [ ] Validasi registry selesai sebelum collection diubah.
- [ ] Source checksum dibandingkan dengan manifest lama.
- [ ] Collection schema/version dan embedding model dicatat.
- [ ] Chunking version/config dicatat.
- [ ] Ekstraksi error per file dilaporkan dengan aman.
- [ ] Page source tetap traceable.
- [ ] Chunk ID memakai stable `policy_id`.
- [ ] Metadata mandatory melekat pada setiap chunk.
- [ ] Empty/short/non-substantive chunks difilter secara deterministik.
- [ ] Exact text duplicate didedup dalam satu policy.
- [ ] Identical text pada policy berbeda tidak kehilangan provenance.
- [ ] Ordering policy/page/chunk deterministic.
- [ ] Tidak ada embedding atau full text di manifest.
- [ ] Dry-run summary menunjukkan added/replaced/unchanged/error counts.
- [ ] Collection lama belum dihapus sebelum semua preflight lulus.

## 6. Controlled Build Checklist

- [ ] Versi Chroma supported diselaraskan dengan constraint environment.
- [ ] Contract test `where`, `$and/$or`, dan `$in/$nin` lulus.
- [ ] Backup/rebuild strategy disetujui manusia.
- [ ] Initial v0.3 migration memakai collection terpisah atau replacement yang
      recoverable.
- [ ] Batch embedding dibatasi untuk laptop 2-core.
- [ ] Model embedding dimuat sekali.
- [ ] Stale chunks untuk policy berubah dihapus sebelum replacement.
- [ ] Collection count sama dengan manifest chunk total.
- [ ] Query smoke test hanya mengembalikan eligible pack.
- [ ] Cross-domain leakage test lulus.
- [ ] Corpus fingerprint cocok dengan manifest.
- [ ] `vector_db/` dan manifest generated tetap ignored Git.

## 7. Routing Acceptance Checklist

- [ ] `government_public + generic` mengaktifkan `government_generic` saja.
- [ ] Healthcare mengaktifkan healthcare pack tanpa education/environment.
- [ ] Education mengaktifkan education pack tanpa healthcare/environment.
- [ ] Environment mengaktifkan environment pack tanpa healthcare/education.
- [ ] `generic_non_government` tidak otomatis mengaktifkan policy pemerintah.
- [ ] Unknown governance context diblokir sampai pilihan eksplisit.
- [ ] Unknown domain jatuh ke generic tanpa domain policy.
- [ ] Evidence need menentukan document type/topic yang eligible.
- [ ] Empty routing tidak fallback ke seluruh corpus.
- [ ] Routing reason dan warning JSON-safe serta dapat diaudit.
- [ ] Filter condition/value canonical dan urutannya deterministic.

## 8. Evidence and Alignment Checklist

- [ ] Result mempertahankan `chunk_id`, `source`, `page`, dan `text`.
- [ ] Routed result menambahkan policy/pack/domain/document type.
- [ ] Evidence cumulative antar-attempt dan dedup konservatif.
- [ ] Attempt tetap maksimum dua.
- [ ] Retry tidak memperluas eligibility secara diam-diam.
- [ ] Sufficiency v0.2 dihitung terpisah dari alignment.
- [ ] Evidence misaligned tidak menaikkan aligned coverage.
- [ ] Mechanically sufficient tetapi misaligned tidak membuka Gemini.
- [ ] No evidence/not applicable dibedakan dari retrieval error.
- [ ] Distance tidak dianggap semantic truth atau legal relevance.
- [ ] Tidak ada embedding, secret, atau duplicate full evidence dalam attempt
      history.

## 9. State, Traceability, and Report Checklist

- [ ] Governance context dan selected domain masuk active fingerprint.
- [ ] Registry/corpus fingerprint perubahan mereset downstream evidence.
- [ ] Context/domain change mereset sufficiency, retry, Gemini, traceability,
      report, dan agent state/audit.
- [ ] Same fingerprint rerun tidak menjalankan retrieval/Gemini kembali.
- [ ] Reviewer tetap memvalidasi `chunk_id`, `source`, dan `page`.
- [ ] Policy ID/pack/domain ditautkan secara additive pada trace/report.
- [ ] Legacy evidence test doubles tetap dapat dipakai pada compatibility path.
- [ ] Report tetap JSON-safe dan tidak menyimpan registry/vector/raw PDF.
- [ ] Schema report hanya diubah jika ditemukan breaking contract nyata.

## 10. Future Automated Test Strategy

### Registry and ingestion

- registry valid/invalid, duplicate ID, missing file, checksum mismatch;
- mapping dua filename baseline ke stable policy IDs;
- stable chunk IDs dan deterministic repeated ingestion;
- primitive chunk metadata dan manifest JSON safety;
- replacement policy menghapus stale chunks;
- duplicate text lintas policy mempertahankan provenance;
- corpus fingerprint berubah hanya untuk input retrieval-relevant.

### Chroma and retrieval

- metadata filtering pada versi supported;
- AND/OR dan homogeneous IN behavior;
- collection isolation dan empty filter handling;
- ranking/result compatibility v0.2;
- no cross-domain leakage;
- no network dan fake embedder/collection pada unit tests.

### Router, sufficiency, and state

- government/generic, healthcare, education, environment routing;
- non-government safe fallback;
- evidence need/query templates dan deterministic refinement;
- domain/pack/type/topic alignment;
- bounded cumulative retry;
- fingerprint reset pada domain/context/corpus change;
- traceability dengan metadata additive;
- report JSON safety;
- seluruh 212 regression v0.2 tetap hijau.

## 11. Recommended Implementation Phases

### Phase A — Policy/domain data models

Tambah typed IDs, registry records, validation, dan serialization tanpa
menyentuh retrieval path.

### Phase B — Policy registry

Buat JSON registry initial six policies, tetapi policy tanpa verified local PDF
belum eligible ingestion. Test mapping dua file existing.

### Phase C — Ingestion metadata and manifest

Tambahkan checksum, stable chunk ID, document/chunk metadata, dry-run, manifest,
dan controlled collection migration.

### Phase D — Metadata-filtered retrieval

Tambahkan filter contract opsional sambil mempertahankan result v0.2. Kunci
compatibility Chroma melalui tests.

### Phase E — Deterministic router

Implementasikan governance/domain/need/pack/type/topic eligibility dan safe
empty routing.

### Phase F — Domain-aware alignment

Tambahkan multi-dimensional alignment di samping sufficiency v0.2; pertahankan
bounded retry.

### Phase G — State and report integration

Integrasikan fingerprint/reset, compact session state, trace metadata, dan
additive report fields.

### Phase H — Initial corpus ingestion

Hanya setelah empat PDF baru lolos acquisition gate dan dua baseline lolos
integrity re-check. Jalankan controlled build lokal dengan approval manusia.

### Phase I — Cross-domain acceptance

Uji generic, healthcare, education, dan environment; no cross-domain leakage;
Gemini tetap human-approved; traceability tetap deterministik.

Setiap phase kecil, testable, dan reversible. Tidak ada big-bang rewrite atau
framework agent baru.

## 12. Stop Conditions

Hentikan acquisition/ingestion jika:

- source bukan official atau status tidak dapat diverifikasi;
- PDF rusak, bukan dokumen yang dimaksud, atau membutuhkan OCR yang belum
  disetujui;
- checksum/file tidak cocok registry;
- relation amendment/revocation ambigu;
- Chroma supported version belum diputuskan;
- metadata filter tests gagal;
- collection update berisiko menghapus corpus tanpa recovery plan;
- proposed routing dapat mencampur policy domain secara diam-diam.

## 13. Actions Explicitly Deferred

- Download empat PDF baru.
- Ingest/re-embed policy.
- Membuat atau memodifikasi vector DB.
- Memindahkan dua PDF existing.
- Menambah phase-2 policy.
- Mengubah RAG, agent, Gemini, report, dependencies, atau product tests.
- Menjalankan release/commit/push/merge/tag.
